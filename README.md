# Поллиноз-карта Кубани

Экспериментальный ГИС-стенд: модель переноса пыльцы, планирование покоса, информационный прогноз и проверка данных. **Это не клинически валидированный продукт и не утверждённый источник управленческих решений.** Стартовые очаги, ряды, население и клиники синтетические или приблизительные; карта использует интернет-подложки, при их недоступности показывается нейтральный фон. Импорт файлов не подтверждает их подлинность. Не вводите реальные персональные или медицинские данные до независимой проверки, организации защиты и правового согласования.

## Быстрый запуск на ноутбуке

Нужны Python 3.11 или 3.12, Node.js 22.12+ и npm. Для первоначальной установки зависимостей нужен интернет. Заранее запустите скрипт и дождитесь успешной сборки: при последующих запусках он использует установленное окружение и сохранённые `node_modules`. Если lock-файл изменился, выполняется `npm ci` (потребуется сеть либо полный npm-кэш). Программа и локальная синтетическая погода после установки могут работать без интернета.

**Windows 11**, из PowerShell в корне проекта:

```powershell
.\scripts\start_local.bat
```

Скрипт пробует `py -3.12`, затем `py -3.11`; также можно заранее создать `.venv` с подходящей версией Python. Скрипт открывает отдельное окно API; после остановки Vite закройте и окно API. Команды для Linux/macOS:

```bash
./scripts/start_local.sh
```

Откройте `http://localhost:5173`; `/docs` доступен через тот же адрес. Скрипты по умолчанию задают `DEMO_MODE=true`, `OFFLINE=false`: публичные демо-роли доступны из верхней панели, погода запрашивается из Open-Meteo, при ошибке используется кэш или синтетическая климатология. Для других настроек задайте переменные окружения до запуска. Локальная SQLite и фото — в `backend/data/`; файл модели пересоздаётся при старте. Скрипты слушают только localhost. Занятые порты 5173 и 8001 надо предварительно освободить. Первоначальная установка, тайлы OpenStreetMap, Esri и CARTO, а также браузерный Swagger UI (`/docs`, jsDelivr CDN) требуют интернет. Если тайлы недоступны, карта показывает нейтральную подложку, но не автономную карту улиц.

Демо-пароль и логины публичные, запрашиваются интерфейсом у `/api/v1/auth/demo-accounts`. Печать ведомости и бюллетеня — кнопками соответствующих вкладок, затем системный диалог печати/PDF. Ведомость отражает текущие фильтры и доступные роли наряды; параметры калькулятора в ней **не являются архивом параметров, по которым создавались наряды**. Бюллетень персональный, не является заключением врача.

## VPS: Docker Compose + PostgreSQL + Nginx

Требуются Docker Engine и Compose plugin на Ubuntu, свободный порт 80, интернет для сборки образов и, при `OFFLINE=false`, доступа к Open-Meteo. По умолчанию HTTP порт опубликован только на `127.0.0.1`.

```bash
cp .env.example .env
chmod 600 .env
# Отредактируйте .env: задайте POSTGRES_PASSWORD, JWT_SECRET_KEY и EDDS_MIS_API_KEY.
# Например, каждый секрет можно независимо сгенерировать: openssl rand -hex 32
# Для POSTGRES_PASSWORD используйте буквы и цифры: пароль вставляется в URL БД.
docker compose config -q
docker compose up -d --build
docker compose ps
docker compose logs -f backend
```

`.env` исключён из Git. Compose поднимает PostgreSQL 16 и API без публикации их портов; Nginx отдаёт SPA на своём порту 80 (на хосте `127.0.0.1:80` по умолчанию) и проксирует `/api/`, `/docs`, `/openapi.json`. Dockerfile API работает непривилегированным пользователем, используется один worker; данные PostgreSQL и файлы модели/фото — в независимых именованных volumes `postgres_data` и `backend_data`. При первом старте они содержат **синтетические данные**, даже при `DEMO_MODE=false`. Резервируйте согласованные снимки БД и файлов (`pg_dump` плюс volume `backend_data`) и проверяйте восстановление. `docker compose down` сохраняет volumes; `down -v` уничтожает данные.

### HTTPS перед внешним доступом

Типовой вариант: укажите в `.env` `WEB_PORT=8080`, настройте DNS домена на VPS и откройте входящие порты 80/443 для **хостового** Nginx. Получите сертификат Let's Encrypt (например, `sudo certbot certonly --standalone -d example.org`, при свободном порте 80). Скопируйте `deploy/host-nginx-tls.conf.example` в конфигурацию хостового Nginx, замените домен и пути сертификата, проверьте `sudo nginx -t` и перезапустите Nginx. Настройте автоматическое продление сертификата с reload Nginx и проверьте `certbot renew --dry-run`. После изменения `.env` пересоздайте стек `docker compose up -d`. Пример требует ручной адаптации под вашу систему; до проверки сертификата и firewall не вводите реальные учётные данные.

**Важно: поставляемый Nginx слушает только HTTP.** Не передавайте пароли, токены, фото и персональные данные через публичный HTTP. До открытия доступа установите HTTPS на доверенном обратном прокси/балансировщике с действительным сертификатом, ограничьте доступ к HTTP только от него, настройте firewall и обновления. Для геолокации браузера тоже нужен HTTPS (или localhost). Базовые заголовки Nginx и секреты не делают систему готовой к эксплуатации: отсутствуют защита от перебора, управление согласием, полноценные миграции, аудит, шифрование и разграничение врачей по пациентам. Нужны отдельные security/privacy review, резервирование, мониторинг и валидация модели. Не объявляйте систему медицинским сервисом без этих работ.

Compose по умолчанию выставляет `DEMO_MODE=false`, `OFFLINE=false`. В этом режиме без непустых `JWT_SECRET_KEY` и `EDDS_MIS_API_KEY` API не стартует, список демо-аккаунтов отключён, демо-пользователи не создаются и старые демо-токены не принимаются. `JWT_SECRET_KEY` должен оставаться стабильным и случайным; смена отключит существующие JWT. Сохраняйте ключи вне Git, ограничьте права на `.env` и резервные копии.

Создайте собственных пользователей **после запуска**, без передачи пароля в аргументах командной строки:

```bash
docker compose exec -it backend python -m app.create_user --username operator --role admin
docker compose exec -it backend python -m app.create_user --username dispatcher1 --role dispatcher
docker compose exec -it backend python -m app.create_user --username team1 --role brigade
```

Пароль вводится интерактивно дважды, минимум 12 символов. Возможные роли: `admin`, `dispatcher`, `brigade`, `doctor`, `patient`. Вход — кнопка «Вход» в верхней панели. Пациенты также могут зарегистрироваться через API `/auth/register`; регистрация не выдаёт привилегированные роли. Фотографии выдаются только через авторизованный API: администратору, диспетчеру или назначенной бригаде; публичного `/uploads` больше нет.

`OFFLINE=false` разрешает живые запросы к Open-Meteo, но при ошибке сеть/кэш могут привести к синтетической климатологии; источник показан на экране. Настройки `TELEGRAM_BOT_TOKEN` и `ENABLE_LIVE_TELEGRAM=true` разрешают реальную ручную отправку Telegram на текущую дату — не включайте без проверки и согласий. SMS-провайдер не реализован; автоматического планировщика и гарантии exactly-once нет. Лог `logged_offline_demo` не подтверждает отправку. `EDDS_MIS_API_KEY` используется в заголовке `X-API-Key`, либо пакет доступен с JWT администратора/диспетчера. Дополнительные переменные — в `.env.example` и `backend/README.md`.

## Собственные данные

Войдите администратором → вкладка «Точность модели». Там доступны шаблоны и загрузка:

* CSV UTF-8 суточных данных с `date,pollen_count,tmax,tmin,dew,precipitation,wind_speed` или недельных `year,week,pollen_count` и необязательных погодных полей. Минимум 10 записей и оба класса относительно порога в первом году для обучения. Недельные значения не превращаются в вымышленные суточные.
* GeoJSON WGS84 с полигонами, площадью `area_ha` и спектральными каналами `B04,B08,B11` либо `NDVI`. При существующих нарядах замена очагов запрещена.

Загрузка заменяет соответствующий набор. Метка `uploaded_dataset` означает лишь «загружено оператором», не верификацию; недостающие погодные признаки могут оставаться синтетическими. Сброс демо восстанавливает синтетический набор и при отдельном подтверждении удаляет **все наряды**, но не удаляет их фотографии. Смотрите формат, ограничения и описание модели в `backend/README.md`.

## Проверки

```bash
cd backend && OFFLINE=true ../.venv/bin/pytest -v
cd ../frontend && npm ci && npm run build
CHROMIUM_PATH=/путь/к/chromium npm run test:e2e
CHROMIUM_PATH=/путь/к/chromium npm run test:mobile
```

Тесты используют временную SQLite и не меняют данные стенда. `test:e2e` (`test:map`) запускает настоящий Chromium и проверяет карту на 360/390/430/1440 px, отключение тайлов, атрибуцию, переключение слоёв, точечный прогноз, передачу адреса и формирование целевого наряда. `test:mobile` проверяет мобильные формы и два печатных представления. Нужен установленный браузер, автоматической загрузки нет. На Windows задайте `BACKEND_PYTHON` полным путём к `.venv\Scripts\python.exe`. Старый JSDOM-тест `frontend/tests/e2e.cjs` сохранён как исторический, но не совместим с Leaflet-интерфейсом и не запускается через `test:e2e`. Дополнительный PostgreSQL smoke-тест: установите `pgserver==0.1.4` и выполните из `backend`: `PYTHONPATH=. ../.venv/bin/python tests/postgres_smoke.py` (Linux x86_64). Сохранённые текстовые результаты этапа 5 относятся к прежнему интерфейсу.


### География и ограничения карты

Начальные 189 очагов — воспроизводимые синтетические квадраты, а не обнаруженные участки амброзии. При новом заполнении БД они расположены в нескольких северных зонах Краснодара, но **не проверены по географической маске водоёмов**: попадание в небольшие реки и пруды не исключено. Уже существующая БД автоматически не перезаполняется. Сброс демо удаляет наряды и требует отдельного подтверждения; не выполняйте его без резервной копии. Для рабочих данных необходимы проверенные оператором геометрии.

Слой пыльцы интерполирует расчётную сетку 1 км, а не реальные измерения. Процент в сценарии умного покоса — сравнение расчётного приземного шлейфа с вариантом без покоса, а не общей концентрации. Прогноз точки складывает городской фон и локальный шлейф, поэтому источники могут учитываться дважды. При выборе «отправить бригаду» наряд ещё не создаётся: диспетчер должен выбрать бригады и подтвердить пакет. Подписка с карты создаётся только после заполнения и подтверждения формы.

### Спутниковый мониторинг и локальный GeoTIFF

Войдите как **администратор** и выберите «Спутниковый скан Sentinel-2 (Live)» в слоях карты или во вкладке «Точность модели». При `OFFLINE=false` сервер запрашивает летнюю сцену Sentinel-2 L2A с облачностью ниже 20% из Earth Search и контуры участков из OpenStreetMap через Overpass. Растровые каналы B04/B08/B11/SCL считываются в общей сетке 512×512; применяются `scale` и `offset` каждого канала из метаданных STAC. Учитываются только пиксели SCL «растительность», а участки, пересекающие лес или парк OSM, исключаются. Показываются ID сцены, дата, облачность и её превью, если каталог предоставляет доверенный адрес; неполное покрытие области указано в результате.

**Это скрининг растительности, а не определение амброзии.** NDVI не распознаёт виды растений. OSM и SCL могут содержать ошибки или пропуски; все участки требуют полевой проверки, как и оценки площади/опасности. Новый скан добавляет кандидатов и обновляет соответствующие ранее обнаруженные OSM-кандидаты, но не заменяет демо-данные и операторский импорт; участки с нарядами не перезаписываются. Источник и ID сцены сохраняются у каждого кандидата. Необходимы доступ к Overpass, Earth Search и публичным S3 COG, работоспособность которых зависит от сети и внешних сервисов; время и объём передачи не гарантируются. `OFFLINE=true` явно отключает живой скан.

В этой же вкладке доступен локальный GeoTIFF: файл B04 с отдельным B08 либо многоканальный файл; сетки должны совпадать, CRS и геопривязка обязательны, файл должен целиком находиться в области Краснодара. Укажите номера каналов и масштаб/сдвиг **по метаданным файла**, например `0.0001` и `-0.1`, только если они действительно заданы для ваших данных. Каждый файл — до 25 МБ. Без SCL и полигонов OSM локальный анализ **не исключает воду, облака, лес и застройку**; это пользовательские данные (`uploaded_geotiff`), а не спутниковый live-скан. Числа NDVI — расчёт по фактическим значениям файла; геотеги и подлинность исходника не проверяются.

API администратора: `POST /api/v1/satellite/scan-live`, `POST /api/v1/satellite/detect-geotiff` (multipart `b04_tif`, необязательный `b08_tif`, `red_band`, `nir_band`, `reflectance_scale`, `reflectance_offset`); `GET /api/v1/satellite/latest-scene` возвращает последнюю сохранённую сцену.

Демо-ограничение воды использует линию Кубани Natural Earth 1:10m (public domain) с запасом и широкую южную запретную зону, включающую примерное расположение излучины, Карасуна и водохранилища. Это **не полный векторный слой водоёмов**: для малых прудов и рек вне неё пересечение не исключено. Тест гарантирует отсутствие пересечений именно с этой ограничительной геометрией, а не доказанную сушу для каждого полигона. Для строгой проверки нужна актуальная проверенная водная маска. Демо-данные и несуществующие амброзийные очаги нельзя считать реальными.
